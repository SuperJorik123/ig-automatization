# IG Automatization — project guide

PC-side queue manager + Android driver for posting photos and scrolling reels on Instagram. Posts live in `posts/` as `NNN.jpg` + `NNN.json` (caption + hashtags); the Angular UI in `ui/` queues new ones; `modules/instagram/upload_post.py` drives IG over ADB via uiautomator2. Code is organised per platform under `modules/` (`instagram`, `telegram`, `twitter`, `youtube`, `facebook`), plus `modules/newsroom/` (the client's WordPress → Telegram bot, formerly the `client/wp-newsbot` branch — same checkout, its own process), with cross-cutting pieces in `shared/` and the web layer (`server.py`, `ui/`) + media queue (`posts/`) at the repo root.

## Layout

Per-platform modules under `modules/`, cross-cutting code under `shared/`, the web layer (`server.py`, `ui/`) and the media queue (`posts/`) at the repo root:

```
modules/
  instagram/   upload_post.py (phone/ADB), graph.py (Graph API — no phone), caption.py (media + headline → full caption), main.py, dump_ui.py, human_swipe.py, analyze_swipes.py, visualize_swipes.py
  telegram/    telegram_bot.py (IG trigger), news_bot.py (manual broadcaster + autopilot host), collector.py, scorer.py, smart_filter.py, dispatcher.py, autopilot.py, reactions.py, publisher.py, translator.py, queue_store.py, smm.py, branded.py (brand-it flow's pure half), groups.py (GMN/JNN account groups)
  twitter/     poster.py — Tweepy video+photo posting (v1.1 media upload + v2 tweet); download-from-X lives in shared/reel_downloader.py
  youtube/     uploader.py (Data API v3 upload, per-account OAuth under credentials/youtube/), publisher.py (translate-per-channel fan-out)
  facebook/    poster.py (stub) — nothing implemented yet
  newsroom/    the CLIENT's WordPress → Telegram bot (main.py, wp.py, rewrite.py, publish.py, orders.py, smm.py, store.py, sites/*.json) — own token NR_BOT_TOKEN, own DB, own BulkFollows key; separate systemd service
shared/
  config.py            .env loading + PHONE_ADDRESS / POSTS_DIR / credentials
  credentials.py       credentials/brands/<name>.json (one file per brand) -> os.environ, loaded by config.py
  reel_downloader.py   yt-dlp downloader (Instagram + Twitter/X URLs)
  branding.py          branded-clip renderer (logo + lower-third headline via ffmpeg)
  photo_card.py        news-card photo renderer (hero + circular insets + scrim + logo + headline, Pillow)
  vision.py            what the media actually shows — the call that runs BEFORE the caption's search
  public_media.py      expose(path) -> (public https URL, cleanup) for APIs that fetch media instead of taking an upload (nginx dir on the VPS)
server.py    FastAPI backend (root)
ui/          Angular frontend (root)
posts/       shared media queue (root); posts/posted/ holds archives
brands/      per-brand logo.png (brands/<name>/logo.png); assets/fonts/ holds the repo-shipped font used for headlines
```

Every entrypoint puts the repo root on `sys.path` (the scripts via a 3×-`dirname` bootstrap at the top of the file; `server.py` via its existing `sys.path.insert`) so `from shared import …` / `from modules.instagram import …` resolve whether the file is run directly (`py modules/instagram/upload_post.py`) or imported.

## Files

| File | Purpose |
| ---- | ------- |
| `server.py` | FastAPI backend on `:8000` (repo root). Receives uploads from the UI, writes them into `posts/`, optionally fires `modules.instagram.upload_post`. Also accepts a `url` form field — when an Instagram URL is pasted, calls `reel_downloader.download_media(url, stub, kind=post_type)` first instead of expecting a multipart file. The stub picks `.mp4` for reels / `.jpg` for posts; yt-dlp overrides the extension with the real one. CORS open to `http://localhost:4200`. |
| `shared/config.py` | Loads the repo-root `.env` and exposes `DEVICE_ID` (from `PHONE_ADDRESS`, USB-serial fallback), `POSTS_DIR`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `IG_ACCOUNTS`. Every entrypoint imports it so `.env` and `posts/` resolve to the root no matter which subfolder the file lives in. |
| `shared/reel_downloader.py` | Fetches Instagram/Twitter media by URL via `yt-dlp` (no token / login / Selenium required — pulls the file directly from `fbcdn.net`). Exposes `is_instagram_url(s)`, `is_twitter_url(s)`, `download_media(url, dest_path, kind="reel"\|"post")`; `download_reel` is kept as a backwards-compat alias. **`download_any(url, dest_stub) -> (paths, caption)` is what callers should use**: yt-dlp reel → yt-dlp post → `download_photos` (gallery-dl), re-raising the FIRST yt-dlp error when all three fail. `download_photos` shells out to `py -m gallery_dl` (the console script isn't on PATH here), renames the result onto `<stub>_1.jpg`, `<stub>_2.png`, … and caps a carousel at `MAX_PHOTOS = 10` (Telegram album limit). yt-dlp can't fetch photo-only tweets or most IG photo posts — that's what the gallery-dl leg is for; login-gated IG posts additionally need `GALLERY_DL_COOKIES_BROWSER=chrome` (or firefox/edge) in `.env` so gallery-dl reuses that browser's session. **If a public reel throws that same error**, yt-dlp is outdated (IG breaks it every few months): `py -m pip install -U yt-dlp`, then restart any running bots — a live process keeps the old module in memory. |
| `shared/branding.py` | Branded-clip renderer: one ffmpeg pass burns `brands/<name>/logo.png` (205 px wide, 82 px from the right edge, 102 px from the top) and a lower-third headline onto a 1080×1920 blur-fill canvas. All geometry is measured off the reference clips at the repo root (`example.MP4`, `newlinebug.mp4`) — see the module docstring before changing a constant. Three things are easy to get wrong: **(1)** the banner box is **fixed** (x 110, 856 px wide, via drawtext `boxw` + 4-value `boxborderw`) — it must not shrink to the headline, so rows wrap by measured **pixel** width (`wrap_to_px`, advance widths via fontTools), not character count; **(2)** rows are separated by a bare **CR** — ffmpeg 8's drawtext breaks on a LF *and draws it* as a missing-glyph box; **(3)** `strip_unrenderable` drops emoji/keycaps/invisibles the font has no glyph for (letters are never dropped, so a CJK headline shows boxes instead of silently losing words). Font is the system Segoe UI Bold → Arial Bold → shipped DejaVu (much heavier — a fallback, not the design). Headline goes in via drawtext `textfile=` — never interpolated into the filter. Per-brand colors/font/size come from `brands/<name>/style.json` — all thirteen brands have one. That file also carries the brand's **`writing_style`**, the one key in it that has nothing to do with the render: `load_writing_style(brand_dir)` returns it for `modules/instagram/caption.py`, `load_style` deliberately does not (the ffmpeg path must never see a paragraph of prose), and unlike the colours it **never raises** — a missing or broken voice just means the neutral wire register. **Renders at most `RENDER_BATCH` brands per ffmpeg pass** (`BRAND_RENDER_BATCH`, default 4): every extra output in a pass is another x264 encoder in the same process — measured ~0.5 GB for the first brand and ~390 MB each after it, so all thirteen in one pass peaked at 5.0 GB and OOM'd the 2 GB VPS (batched: 1.65 GB, and the wall time didn't move — the encodes dominate, not the shared decode/blur the single pass was saving). All-or-nothing spans every batch: a failure removes the outputs of finished batches too, because news_bot catches it and retries brand-by-brand. Jobs are all validated before the first ffmpeg starts. Pure/blocking; callers use `asyncio.to_thread`. |
| `shared/photo_card.py` | **News-card photo renderer** (the photo twin of `branding.py`, pure Pillow — no ffmpeg). `render_card(hero, headline, logo_path, out, insets=[...], layout="insets", size=(1080,1350), focus=EYELINE)` composes one of **four reference designs** (`example1..4.png` at the repo root) — and `layout` changes ONLY the photo layer, never the scrim / divider / logo / headline above it, which is what keeps the brand look constant whichever design the operator taps. `"insets"` (the default, example2) is the template below; `"solo"` (example1) is the hero alone and ignores `insets`; `"split"` (examples 3 and 4) lays the hero and `insets` out as **2 or 3 full-height panels, edge to edge, no gutter** — `split_fill` hands out integer widths that sum to W, because a rounded-down slice leaves a one-pixel seam. A panel is 540 or 360 px of a landscape source, so a centre crop decapitates an off-centre subject: `panel_fit` steers BOTH axes by **`subject_focus(path)`**, the alpha-weighted centroid of the rembg matte, memoised per (path, mtime, size) so thirteen brands rendering the same three photos pay for one matte each and not thirty-nine. `subject_focus` never raises — no rembg, an unreadable file or an empty matte all fall back to `(0.5, EYELINE)`, the plain centre crop, the same contract as `subject_cutout`. `insets` is therefore "the other photos in the post" (circles, panels or nothing) and an unknown `layout` raises rather than silently rendering the wrong design. The `"insets"` template, measured off `examplepost.png`: hero cover-fit (crop steered by `focus`, the eyes' row in the source, placed at 34 % of the canvas), up to two circular insets top-left/right (white ring + drop shadow, 33 % width, fully inside the frame — 0.355 W diameter, 0.025 W margin, centre at 0.205 H, 7 px ring, all measured off `examplepost.png`), then the hero's **subject cut back on top** of the circles via rembg (`subject_cutout`; model per `CARD_CUTOUT_MODEL`, default `bria-rmbg` ~1 GB auto-downloaded to `~/.rembg` on first use — pre-warm it on the VPS; applied **only inside the circle regions** (`_restrict_to_circles`) with the alpha eroded 2 px + feathered so the background-tinted rim can't halo the circle — outside the circles not a pixel changes; skipped with a log line when rembg is missing or the matte covers < 3 % of the canvas; `render_card(..., cutout=False)` for tests), bottom scrim, split divider rule with the logo in the gap (`LOGO_HEIGHT` 0.09 H — doubled 2026-09-24, the old 0.045 was unreadable on a phone; the headline font is fitted to the room left under it), upper-cased centred headline auto-fitted (font shrinks until ≤3 lines fit; never drops words). All geometry is canvas fractions at the top of the file. Font: Impact → Arial Bold → shipped DejaVu. Blocking; the news bot calls it via `asyncio.to_thread`. CLI: `py shared/photo_card.py hero.jpg --headline "..." --brand mirnews --inset a.jpg --inset b.jpg -o card.jpg` (`--layout solo|insets|split`). |
| `modules/telegram/branded.py` | Brand-it flow's pure half (offline-testable — news_bot exits at import without env): `platforms_for` (which of TG/YT/X/IG at least one rendered brand can publish to, each carrying its own subset of the renders — YouTube hidden past the 180 s Shorts cap and for photo cards; IG offered for both), `expand` (ticked platform indexes → the flat brand×platform pairs `_do_publish` consumes) the **plan card**'s pure half (`default_plan` / `plan_platform_keys` / `brands_summary` / `plan_lines`, `plan_keyboard` and the one-screen `plan_edit_keyboard`) and the platform picker, callback namespace `b:`. `card_layouts(n_photos)` is the design choice — the four reference designs, offered by photo count: ⚪ Circles (`insets`, 2+) / ◧ Split ×2 (`split2`, 2+) / ◫ Split ×3 (`split3`, 3+) / ▭ Photo only (`solo`), and with ONE photo only `solo`; the design row sits **on the plan card itself** (and in the editor), and `render_args(design, photos)` maps a design id onto photo_card's `(hero, layout, insets)` — both splits are photo_card's `"split"`, the id only decides how many photos go in. Also the two pure halves of the operator's reply: **`parse_reply(text) -> (field, value)`** — a reply to an open picker still replaces the headline, unless it opens `info:`, which gives the Instagram caption the operator's source and facts (`info:` with nothing after it takes them back off; the old `caption:` prefix is gone and now reads as a headline) — and **`footage_lines(footage)`**, the single 👁 line a picker shows for a `shared/vision` analysis (the headline check was removed 2026-09-16). The plan editor's **brand rows open collapsed** to one row per account group (`b:g:<i>`) with the thirteen-brand list behind `⚙ Custom…` (`b:custom` / `b:groups`) — `toggle_brand_group` is the tick rule, `modules/telegram/groups.py` the membership. **The publish step picks PLATFORMS, not pairs** — brands are already chosen one step earlier at render time, so the keyboard is 1-4 rows instead of brands×platforms. |
| `modules/telegram/groups.py` | **Account groups (GMN / JNN)** — the one thing both news-bot pickers collapse behind. Thirteen brands is thirteen rows, but a post goes to a whole family, so both pickers OPEN COLLAPSED to one row per group with the full list behind `⚙ Custom…` (`⬅ Groups` goes back). Membership lives in ONE place: `"group": "GMN"` in `credentials/brands/<name>.json` → `BRAND_<NAME>_GROUP` → `brand["group"]`. Tapping a group fills it, tapping a full one clears it, and a **partly** selected group fills first (`◪`) — the selection underneath is the same set either way, so a group tick and a hand edit in Custom compose. `brand_groups` (indexes into the brand list; skips brands with no logo.png — they can't render) and `dest_groups` (indexes into TG_/YT_/TW_DESTINATIONS) — the as-is picker lists CHANNELS, not brands, so a destination is grouped by **the brand that owns that handle** (`@WsWire` is `wswire`'s `tg`), matched case-insensitively without the `@`. A destination no brand claims is Custom-only (`All` still covers it); a group that would select nothing is never offered, and with no group configured anywhere neither picker collapses. Pure, offline-testable, like `branded.py`/`reactions.py`. |
| `modules/instagram/upload_post.py` | Main poster. Pushes media to phone, drives IG's UI through the new flow (see below), archives to `posts/posted/`. Re-exports `DEVICE_ID` from `shared.config` so callers keep using `ig.DEVICE_ID`. |
| `modules/instagram/graph.py` | **Instagram publishing through the Graph API** — no phone. "Instagram API with Instagram Login" flow (Meta app, no Facebook Page), host **`graph.instagram.com` v23.0, never `graph.facebook.com`** (the `IGAA…` tokens only work on the Instagram host). Plain `requests`. Creds per account: `IG_GRAPH_<ACCOUNT>_ACCESS_TOKEN` / `_USER_ID` (account uppercased, non-alnum → `_`, same rule as the Twitter poster; `IG_` alone belongs to the phone accounts). `publish_photo(url, caption, account)` / `publish_reel(url, caption, account)`: POST `/{user}/media` (image_url, or video_url + `media_type=REELS`) → poll `GET /{container}?fields=status_code` until FINISHED (ERROR/EXPIRED and a 10-min timeout fail) → POST `/{user}/media_publish`. The media must sit at a **public https URL** (`shared/public_media.py`) — images JPEG only; 100 API posts per account per rolling 24 h. Caption trimmed to 2200 on a word boundary. Returns the Twitter poster's `{"status": "success"\|"failed", "id"\|"error"}` dict and never raises for API trouble. `refresh_token(account)` (GET `/refresh_access_token?grant_type=ig_refresh_token`) rewrites the token line in `.env` **in place** (keeping the file's CRLF/LF), stamps `IG_GRAPH_<ACCOUNT>_TOKEN_REFRESHED=YYYY-MM-DD` next to it and updates `os.environ`; `refresh_stale(accounts, max_age_days=7)` is what the news bot's daily job calls (no stamp = unknown age = refresh; a token < 24 h old can't be refreshed — stamp it by hand when pasting one). Blocking; the bot uses `asyncio.to_thread`. CLI: `py modules/instagram/graph.py --account wswiremedia --whoami` / `--refresh` / `--photo URL --caption "…"` / `--reel URL --caption "…"`. |
| `modules/instagram/caption.py` | **The media → the full Instagram caption.** Instagram is the one platform here that doesn't post the headline: an IG caption is read as the story, so `expand(headline, footage)` makes one OpenRouter call that returns the account's usual shape — the headline, 2-4 short wire-service paragraphs, then a line of hashtags (the model writes only the paragraphs and tags; `compose` puts the brand's headline on top, and `info=` carries the operator's `info:` reply into the prompt as the source of truth) — asked for as a **pool of eight** (`POOL_HASHTAGS`, capped by `_cap_hashtags`, keeping the HEAD because the prompt orders tags most-specific-first) out of which each account draws its own **five** (`MAX_HASHTAGS`); picked relevance-first (every tag has to be something the story is actually about), and among those the high-traffic short form over the long specific one, never reach for its own sake. The model **must be able to search** (`IG_CAPTION_MODEL`, default `openai/gpt-5.6-luna:online` — the cheap 5.6 tier, $0.20/M in / $1.20/M out): the **`:online` suffix** is what gives any OpenRouter model live lookup, and a plain id answers from training data, which defeats the point on a news account. **THE MEDIA GOES IN FIRST (2026-09-14).** `:online` is a search plugin that runs BEFORE the model sees the prompt and builds its query out of that prompt — so a prompt that was only a headline searched the headline's WORDS and returned the most prominent story matching them, which published a caption about Floyd Mayweather over a clip of a different boxer. `footage` is `shared/vision.describe`'s report of what the media actually shows; with it the query is built from the footage and the search drops to **corroboration** — it may add a name, a place, a date, an official response, and anything contradicting the report is the wrong story. `_SYSTEM_FOOTAGE` also picks its **register** from what it has: wire-service when the search confirms a reported event, plain narration of the clip (the bear caption is in the prompt as the model of that mode) when the clip IS the story — the commoner case, and where `#caughtoncamera` / `#viralvideo` are legitimate picks. It bans **restating the headline** in paragraph 1: the old "if the search returns little, write ONE short paragraph and stop" rule is what produced a headline followed by one paragraph saying the headline again, and with footage in hand there is always material. **Falsy `footage` sends the byte-identical request this sent before** (asserted by a test) — vision is best-effort and a failed analysis must cost the caption its detail, not its existence. `_HASHTAG_RULES` is shared by both prompts so the pool `pick_hashtags` deals from is the same shape either way. Two contracts lifted from `modules/telegram/translator.py`: **never raises** (missing key, dead gateway, unknown model id, empty completion → the bare headline, because the render is made and publish is already tapped) and **faithful** (the search sources the headline's own story; the prompt says to write ONE short paragraph rather than pad when the search comes back thin). Sends **no `temperature`** (current OpenAI models on OpenRouter reject a non-default one → APIError → a silently caption-less post) but **does send a deliberately roomy `max_tokens = 8000`**: OpenRouter reserves credit for the WORST CASE up front, so an uncapped call demands a balance covering the model's full 65,536-token ceiling — that 402'd a live caption at a $1.42 balance on 2026-09-09 and shipped the post as the bare headline. The cap is still far above anything a caption needs, so the reasoning-model-runs-out failure the uncapped call was avoiding can't happen either. `_clean` strips the fences / `Caption:` labels / `[2]` citation markers a model adds after being told not to, then `graph.trim_caption` applies the 2200 cap. `IG_CAPTION_ENABLED=0` is the kill switch. **YouTube reuses it** (2026-09-24): `youtube_description(caption, headline)` (pure) cuts a brand's finished IG caption down for the Short — the headline dropped (it is the title), the prose cut to the lead paragraphs up to `YT_DESC_PROSE` (450 chars, at least one paragraph, word-boundary trimmed), the brand's hashtag line kept with `#shorts` appended, `<`/`>` stripped (YouTube rejects the upload over them); news_bot's `_ig_captions` therefore also runs when only a YT pair is selected, one caption per brand across both platforms. **Measured 2026-09-11**: an expansion bills **~$0.049** — the model fires FOUR searches at ~$0.01 each and their results push the prompt to ~42k tokens — against **$0.0004** for a rewrite, so the search is ~80% of a post and the per-account captions are a rounding error on it. **A caption per ACCOUNT, not per language**: twelve of the thirteen brands are `en`, so one shared caption meant every English account published identical text within seconds — duplicate content. The search is still bought once and only the WORDING varies. `plan(brands, seed)` (pure) gives the first account of each language the shared caption — its call is already paid for — and every account after it a rotating `ANGLES` directive; `rephrase(text, angle, lang, style)` is one cheap **searchless** call (`IG_CAPTION_VARIANT_MODEL`, no `:online` — the facts are already in the text being rewritten) that rewrites to that angle, and **translates in the same call when `lang` is given**, so a foreign-language account stays at one call rather than two; `pick_hashtags(text, offset, brand)` (pure, free) deals each account a different **combination** out of the pool — a rotating window wraps after six accounts and there are thirteen brands — keeping the two most specific tags every time and **signing the line with the account's OWN tag** (`brand_tag`/`with_brand_tag`): `#frontiva24` on frontiva24, `#europamonitor` on europamonitor. That tag is **mandatory on every caption the account publishes**, which is why `with_brand_tag` is a function of its own — the bare headline a failed expansion falls back to gets a tag line made for it (news_bot's IG leg calls it on that path). It is built from the BRAND NAME, never the Instagram handle: a handle can carry a dot (`vestra.24`, `daily.news.co`) and Instagram ends a tag at the first non-alphanumeric. It OPENS the tag line, taking the FIRST of the five slots rather than adding a sixth, so the story is dealt one tag fewer and the head is never touched. `seed_for` (crc32, not `hash()`, which is salted per process) rotates the whole deal per post, so an account doesn't open every post the same way. **Angle vs style**: the angle rotates per post and keeps two accounts apart on one story; the `style` — `writing_style` from `brands/<name>/style.json`, loaded by `shared/branding.load_writing_style` — is the same on every post an account publishes, which is what makes it recognisable rather than merely different, and the prompt puts it below SAME FACTS so a voice can't acquire an adjective the source didn't support. A brand with a style is never the one that keeps the shared caption un-rewritten (its voice is the point), so that free ride passes to the first brand of that language with no style; with every brand styled — which is the case for the JNN accounts on Instagram — nobody takes it and the shared caption is only ever a source text. Both calls never raise: a failed rewrite falls back to the shared caption, a failed expansion to the bare headline. Blocking; the news bot calls it via `asyncio.to_thread`. CLI: `py modules/instagram/caption.py "Released footage shows plane crash at Miami International Airport"` (`--media clip.mp4` runs the whole inverted pipeline against a real clip; `--accounts N` prints the post as N accounts would publish it — the only way to see whether the angles are pulling the rewrites apart; `--brands a,b,c` does the same with the real brands, each in its own `style.json` voice). |
| `shared/credentials.py` | **One JSON file per brand, holding everything that brand owns**: `credentials/brands/<name>.json` (git-ignored; `credentials/brands/_example.json` is the tracked template, and files starting with `_`/`.` or ending `.example` are skipped by the loader). **The filename IS the brand name**, matching `brands/<name>/logo.png` — so a brand is two paths, deleting one is deleting its file, and handing a client their own credentials is sending one file with no way to leak a sibling's keys. Each file holds `lang`, `group` (the picker family — see `modules/telegram/groups.py`), `telegram.channel`, `youtube.channel`, the five `twitter.*` keys and the three `instagram.*` fields, replacing a `BRANDS` entry + 4 `BRAND_<NAME>_*` + 5 `TWITTER_<NAME>_*` + 3 `IG_GRAPH_<NAME>_*` lines scattered through `.env`. **Shared services stay in `.env`** (OpenRouter, BulkFollows, SMTP, bot tokens, autopilot knobs) — they were never per-account. `apply()` EXPANDS every file into `os.environ` from `shared/config.py`, right after `load_dotenv`, so every reader is unchanged: the posters still `os.getenv("TWITTER_<ACCT>_…")`, `_parse_brands` still reads `BRANDS`. **Brands load in filename (alphabetical) order**, which is the brand-picker row order. Opt-in (no directory = nothing changes); JSON wins per key, `BRANDS` and `IG_GRAPH_ACCOUNTS` are merged so a half-migrated `.env` keeps working; **unknown keys raise**, naming the file (a `twiter` typo must not silently drop five credentials) and so does malformed JSON — at startup, loudly. `update_instagram_token` rewrites only the owning brand's file and is what `graph.refresh_token` tries before rewriting the `.env` line. Per-account name defaults to the brand name; `"account"` overrides it. YouTube OAuth stays as files under `credentials/youtube/<channel>/`. CLI: `py shared/credentials.py --check` / `--import-env [--force]` (builds one file per brand from the current `.env`). |
| `shared/vision.py` | **What the media actually shows** — the call that runs BEFORE the caption's web search, and the fix for a caption about Floyd Mayweather published over a clip of a different boxer (2026-09). `:online` is a search plugin that runs **before the model sees the prompt** and builds its query out of that prompt, so a headline-only prompt searched the headline's WORDS and got the most prominent story matching them; attaching the video to that same call would not have helped, because the search still fires first. Hence two calls, this one first. `describe(path, headline='') -> dict` sends the media to `IG_VISION_MODEL` (default `google/gemini-2.5-flash` — **natively multimodal WITH AUDIO**, because "people nearby began shouting" is not on screen) and returns `{summary, beats, audible, setting}` (the headline is sent as context only — there is no headline verdict any more); `as_prompt(footage)` is that dict as the block `caption.expand` puts in its prompt. The prompt says **observe, do not identify**: never name a person the media doesn't name, never assume the headline's people are the people on screen — checking exactly that is the point. A local clip travels as a **base64 data URL**: OpenRouter takes a plain https `video_url` only for **YouTube links**, and Gemini reads **public** YouTube videos only — so a "dummy channel" would mean every clip sitting publicly on a channel before publication, which is the exposure that cost three accounts in 2026-08 (see `YT_UPLOADS_ENABLED`). `_analysis_copy` keeps the body sane: one ffmpeg pass to 480p/CRF 30 with **64 kbps mono audio kept**, trimmed to `IG_VISION_MAX_S` (120 s), retried at 360p, and `describe` refuses to send anything over `IG_VISION_MAX_MB` (18) rather than posting a 60 MB request. Photos skip ffmpeg and go as an `image_url` part. **Never raises** — no key, no ffmpeg, dead gateway, prose instead of JSON, a missing `summary`, an oversized clip all return `{}`, and `{}` is what every consumer already treats as "no footage" (i.e. exactly the behaviour that shipped before this existed). ~$0.005-0.01 a post. Blocking; async callers use `asyncio.to_thread`. CLI: `py shared/vision.py clip.mp4 --headline "…"`. |

    py -m pip install -r requirements.txt

    py -m uvicorn server:app --reload --port 8000

    cd ui
    npm start

    py modules/telegram/telegram_bot.py

    py modules/telegram/dispatcher.py   # the smart filter: scores queued items, auto-uploads >=YT_AUTO_MIN_SCORE videos to YouTube

## Current IG creation flow

`modules.instagram.upload_post.upload_post(d, image_path, caption_body, hashtags, kind=...)` drives the new creation UI end to end. `kind` is `"post"` (photo, default) or `"reel"` (video); the only divergence is which row gets tapped in step 4 — the rest of the flow is assumed identical and we fix selectors as IG diverges.

1. Open IG (`app_start`).
2. Tap **Profile** (bottom-right tab) — `tap_profile_tab`.
3. Tap **+** at the top of the profile screen — `tap_create_button`.
4. Tap **Post** or **Reel** in the bottom-sheet picker, per `kind`. Row order: reel / edits / post / story / highlights / live / AI / Ad — `tap_post_type`.
5. Tap the **latest thumbnail** in the gallery (auto-points at the freshly-pushed file) — `tap_latest_gallery_item`. Selectors cover both `Photo` and `Video` content-descriptions.
6. Tap **Next** after the gallery — `tap_next` (covers `text="Next"` and `description="Next"`, position-agnostic).
7. **Post only**: tap **Next** again on the filter/edit screen. Reels skip this step and land directly on the composer.
8. Tap the caption field (placeholder "Add a caption...") and inject the full caption (body + blank line + space-separated `#tags`) in one shot via uiautomator2's FastInput IME — see `inject_text`.
9. If the caption contained hashtags, the last `#tag` typically triggers IG's autocomplete strip — which overlays Share and blocks the tap. `tap_first_hashtag_suggestion` polls `dump_hierarchy()` for the row's resource-id (`row_hashtag_textview_tag_name`) and taps inside the live bounds (selector RPC silently returns count=0 for this strip on the S23, so we read XML directly). The call is **best-effort** — if the strip never appears within ~6 s we just log and continue.
10. **Dismiss the soft keyboard first** (`hide_keyboard_if_shown`) — on the reel composer Share sits in the right half of the footer at y≈2100 and the Samsung keyboard overlaps it; without this step the synthetic tap lands on the keyboard and IG never sees it. Then tap **Share**.
11. Verify the publish by dumping the hierarchy and looking for `resource-id="com.instagram.android:id/share_button"`. If it's still there the post didn't ship and we raise (`ui_dump_share_fail.xml` for inspection). Note: don't check for the caption hint text — `Write a caption…` / `Add a caption…` is the field's `hint=` attribute and stays in the XML even after the caption is filled, so it false-fires.

On success, `main()` calls `archive_post(...)` to move the image + JSON sidecar from `posts/` to `posts/posted/` so it isn't re-uploaded.

### Why FastInput IME instead of the system clipboard

On modern Samsung / OneUI, `d.set_clipboard(text)` raises `java.lang.SecurityException: Package android does not belong to 2000` — AppOpsManager won't let the shell UID claim the `android` package to call `ClipboardManager.setPrimaryClip`. We sidestep the clipboard entirely: FastInput IME (shipped inside `uiautomator2`) is activated, `send_keys` broadcasts the text to it, the IME injects it into the focused field instantly. The previous IME is restored on the way out so the user's normal keyboard isn't left swapped.
