# IG Automatization — project guide

PC-side queue manager + Android driver for posting photos and scrolling reels on Instagram. Posts live in `posts/` as `NNN.jpg` + `NNN.json` (caption + hashtags); the Angular UI in `ui/` queues new ones; `modules/instagram/upload_post.py` drives IG over ADB via uiautomator2. Code is organised per platform under `modules/` (`instagram`, `telegram`, `twitter`, `youtube`, `facebook`), plus `modules/newsroom/` (the client's WordPress → Telegram bot, formerly the `client/wp-newsbot` branch — same checkout, its own process), with cross-cutting pieces in `shared/` and the web layer (`server.py`, `ui/`) + media queue (`posts/`) at the repo root.

## Layout

Per-platform modules under `modules/`, cross-cutting code under `shared/`, the web layer (`server.py`, `ui/`) and the media queue (`posts/`) at the repo root:

```
modules/
  instagram/   upload_post.py (phone/ADB), graph.py (Graph API — no phone), caption.py (media + headline → full caption), main.py, dump_ui.py, human_swipe.py, analyze_swipes.py, visualize_swipes.py
  telegram/    telegram_bot.py (IG trigger), news_bot.py (manual broadcaster + autopilot host), collector.py, scorer.py, smart_filter.py, dispatcher.py, autopilot.py, reactions.py, publisher.py, translator.py, queue_store.py, smm.py, branded.py (brand-it flow's pure half), groups.py (GMN/JNN account groups)
  twitter/     poster.py — Tweepy video+photo posting (v1.1 media upload + v2 tweet); download-from-X lives in shared/reel_downloader.py
  youtube/     uploader.py (Data API v3 upload, per-account OAuth under credentials/youtube/), publisher.py (translate-per-channel fan-out)
  facebook/    poster.py (stub) — nothing implemented yet
  newsroom/    the CLIENT's WordPress → Telegram bot (main.py, wp.py, rewrite.py, publish.py, orders.py, smm.py, store.py, sites/*.json) — own token NR_BOT_TOKEN, own DB, own BulkFollows key; separate systemd service
shared/
  config.py            .env loading + PHONE_ADDRESS / POSTS_DIR / credentials
  credentials.py       credentials/brands/<name>.json (one file per brand) -> os.environ, loaded by config.py
  reel_downloader.py   yt-dlp downloader (Instagram + Twitter/X URLs)
  branding.py          branded-clip renderer (logo + lower-third headline via ffmpeg)
  photo_card.py        news-card photo renderer (hero + circular insets + scrim + logo + headline, Pillow)
  vision.py            what the media actually shows — the call that runs BEFORE the caption's search
  public_media.py      expose(path) -> (public https URL, cleanup) for APIs that fetch media instead of taking an upload (nginx dir on the VPS)
server.py    FastAPI backend (root)
ui/          Angular frontend (root)
posts/       shared media queue (root); posts/posted/ holds archives
brands/      per-brand logo.png + style.json, one folder per account group (brands/GMN/<name>/, brands/JNN/<name>/ — resolved by `config.brand_dir`); assets/fonts/ holds the repo-shipped font used for headlines
```

Every entrypoint puts the repo root on `sys.path` (the scripts via a 3×-`dirname` bootstrap at the top of the file; `server.py` via its existing `sys.path.insert`) so `from shared import …` / `from modules.instagram import …` resolve whether the file is run directly (`py modules/instagram/upload_post.py`) or imported.

## Files

| File | Purpose |
| ---- | ------- |
| `server.py` | FastAPI backend on `:8000` (repo root). Receives uploads from the UI, writes them into `posts/`, optionally fires `modules.instagram.upload_post`. Also accepts a `url` form field — when an Instagram URL is pasted, calls `reel_downloader.download_media(url, stub, kind=post_type)` first instead of expecting a multipart file. The stub picks `.mp4` for reels / `.jpg` for posts; yt-dlp overrides the extension with the real one. CORS open to `http://localhost:4200`. |
| `shared/config.py` | Loads the repo-root `.env` and exposes `DEVICE_ID` (from `PHONE_ADDRESS`, USB-serial fallback), `POSTS_DIR`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `IG_ACCOUNTS`. Every entrypoint imports it so `.env` and `posts/` resolve to the root no matter which subfolder the file lives in. |
| `shared/reel_downloader.py` | Fetches Instagram/Twitter media by URL via `yt-dlp` (no token / login / Selenium required — pulls the file directly from `fbcdn.net`). Exposes `is_instagram_url(s)`, `is_twitter_url(s)`, `download_media(url, dest_path, kind="reel"\|"post")`; `download_reel` is kept as a backwards-compat alias. **`fetch(url, dest_stub) -> (paths, caption, source)` is what callers should use** (`download_any` is the same without `source`); `source` is `source_post(url, caption, meta)` = `{platform: x|reddit|instagram, url, text, author}` — the post the clip came from, built from yt-dlp's info dict / gallery-dl's sidecar that used to be discarded: `text` is the tweet / IG caption / for Reddit `reddit_context` (title + body + the uploader's own comments, falling back to the title), `author` a validated handle (X `uploader_id`, IG `channel`, Reddit `uploader`; never a display name or numeric id), "" when absent — it never blocks a post. The downloader chain is: yt-dlp reel → yt-dlp post → `download_photos` (gallery-dl), re-raising the FIRST yt-dlp error when all three fail. `download_photos` shells out to `py -m gallery_dl` (the console script isn't on PATH here), renames the result onto `<stub>_1.jpg`, `<stub>_2.png`, … and caps a carousel at `MAX_PHOTOS = 10` (Telegram album limit). yt-dlp can't fetch photo-only tweets or most IG photo posts — that's what the gallery-dl leg is for; login-gated IG posts additionally need `GALLERY_DL_COOKIES_BROWSER=chrome` (or firefox/edge) in `.env` so gallery-dl reuses that browser's session. **If a public reel throws that same error**, yt-dlp is outdated (IG breaks it every few months): `py -m pip install -U yt-dlp`, then restart any running bots — a live process keeps the old module in memory. |
| `shared/branding.py` | Branded-clip renderer — **the one video treatment every source gets** (X, Reddit, IG, Telegram upload all go through `_do_render`; "Post as-is" stays raw). **Since 2026-10-18 the clip fits 1080×`FG_H` (1708, `FG_SCALE` 0.89)**, so a 9:16 clip is shrunk to 961×1708 and the blur frames it (before, a 9:16 source filled the canvas and the treatment was invisible — why IG reposts looked untreated); 16:9/1:1/4:5 are width-bound and unchanged. **The banner is anchored by its BOTTOM** at `BANNER_BOTTOM` 0.79 (`y=h*0.79-12-text_h`), so however many rows it wraps to it stays out of Instagram's UI in the bottom 20 %. One ffmpeg pass burns `brands/<group>/<name>/logo.png` (205 px wide, 82 px from the right edge, 102 px from the top) and a lower-third headline onto a 1080×1920 blur-fill canvas. All geometry is measured off the reference clips at the repo root (`example.MP4`, `newlinebug.mp4`) — see the module docstring before changing a constant. Three things are easy to get wrong: **(1)** the banner box is **fixed** (x 110, 856 px wide, via drawtext `boxw` + 4-value `boxborderw`) — it must not shrink to the headline, so rows wrap by measured **pixel** width (`wrap_to_px`, advance widths via fontTools), not character count; **(2)** rows are separated by a bare **CR** — ffmpeg 8's drawtext breaks on a LF *and draws it* as a missing-glyph box; **(3)** `strip_unrenderable` drops emoji/keycaps/invisibles the font has no glyph for (letters are never dropped, so a CJK headline shows boxes instead of silently losing words). Font is the system Segoe UI Bold → Arial Bold → shipped DejaVu (much heavier — a fallback, not the design). Headline goes in via drawtext `textfile=` — never interpolated into the filter. Per-brand colors/font/size come from `brands/<group>/<name>/style.json` — all thirteen brands have one. That file also carries the brand's **`writing_style`**, the one key in it that has nothing to do with the render: `load_writing_style(brand_dir)` returns it for `modules/instagram/caption.py`, `load_style` deliberately does not (the ffmpeg path must never see a paragraph of prose), and unlike the colours it **never raises** — a missing or broken voice just means the neutral wire register. **Renders at most `RENDER_BATCH` brands per ffmpeg pass** (`BRAND_RENDER_BATCH`, default 4): every extra output in a pass is another x264 encoder in the same process — measured ~0.5 GB for the first brand and ~390 MB each after it, so all thirteen in one pass peaked at 5.0 GB and OOM'd the 2 GB VPS (batched: 1.65 GB, and the wall time didn't move — the encodes dominate, not the shared decode/blur the single pass was saving). All-or-nothing spans every batch: a failure removes the outputs of finished batches too, because news_bot catches it and retries brand-by-brand. Jobs are all validated before the first ffmpeg starts. Pure/blocking; callers use `asyncio.to_thread`. |
| `shared/photo_card.py` | **News-card photo renderer** (the photo twin of `branding.py`, pure Pillow — no ffmpeg). `render_card(hero, headline, logo_path, out, insets=[...], layout="insets", size=(1080,1350), focus=EYELINE)` composes one of **four reference designs** (`example1..4.png` at the repo root) — and `layout` changes ONLY the photo layer, never the scrim / divider / logo / headline above it, which is what keeps the brand look constant whichever design the operator taps. `"insets"` (the default, example2) is the template below; `"solo"` (example1) is the hero alone and ignores `insets`; `"split"` (examples 3 and 4) lays the hero and `insets` out as **2 or 3 full-height panels, edge to edge, no gutter** — `split_fill` hands out integer widths that sum to W, because a rounded-down slice leaves a one-pixel seam. A panel is 540 or 360 px of a landscape source, so a centre crop decapitates an off-centre subject: `panel_fit` steers BOTH axes by **`subject_focus(path)`**, the alpha-weighted centroid of the rembg matte, memoised per (path, mtime, size) so thirteen brands rendering the same three photos pay for one matte each and not thirty-nine. `subject_focus` never raises — no rembg, an unreadable file or an empty matte all fall back to `(0.5, EYELINE)`, the plain centre crop, the same contract as `subject_cutout`. `insets` is therefore "the other photos in the post" (circles, panels or nothing) and an unknown `layout` raises rather than silently rendering the wrong design. The `"insets"` template, measured off `examplepost.png`: hero cover-fit (crop steered by `focus`, the eyes' row in the source, placed at 34 % of the canvas), up to two circular insets top-left/right (white ring + drop shadow, 33 % width, fully inside the frame — 0.355 W diameter, 0.025 W margin, centre at 0.205 H, 7 px ring, all measured off `examplepost.png`), then the hero's **subject cut back on top** of the circles via rembg (`subject_cutout`; model per `CARD_CUTOUT_MODEL`, default `bria-rmbg` ~1 GB auto-downloaded to `~/.rembg` on first use — pre-warm it on the VPS; applied **only inside the circle regions** (`_restrict_to_circles`) with the alpha eroded 2 px + feathered so the background-tinted rim can't halo the circle — outside the circles not a pixel changes; skipped with a log line when rembg is missing or the matte covers < 3 % of the canvas; `render_card(..., cutout=False)` for tests), bottom scrim, split divider rule with the logo in the gap (`LOGO_HEIGHT` 0.09 H — doubled 2026-09-24, the old 0.045 was unreadable on a phone; the headline font is fitted to the room left under it), upper-cased centred headline auto-fitted (font shrinks until ≤3 lines fit; never drops words). All geometry is canvas fractions at the top of the file. Font: Impact → Arial Bold → shipped DejaVu. Blocking; the news bot calls it via `asyncio.to_thread`. CLI: `py shared/photo_card.py hero.jpg --headline "..." --brand mirnews --inset a.jpg --inset b.jpg -o card.jpg` (`--layout solo|insets|split`). |
| `modules/telegram/branded.py` | Brand-it flow's pure half (offline-testable — news_bot exits at import without env): `platforms_for` (which of TG/YT/X/IG at least one rendered brand can publish to, each carrying its own subset of the renders — YouTube hidden past the 180 s Shorts cap and for photo cards; IG offered for both), `expand` (ticked platform indexes → the flat brand×platform pairs `_do_publish` consumes) the **plan card**'s pure half (`default_plan` / `plan_platform_keys` / `brands_summary` / `plan_lines`, `plan_keyboard` and the one-screen `plan_edit_keyboard`) and the platform picker, callback namespace `b:`. `card_layouts(n_photos)` is the design choice — the four reference designs, offered by photo count: ⚪ Circles (`insets`, 2+) / ◧ Split ×2 (`split2`, 2+) / ◫ Split ×3 (`split3`, 3+) / ▭ Photo only (`solo`), and with ONE photo only `solo`; the design row sits **on the plan card itself** (and in the editor), and `render_args(design, photos)` maps a design id onto photo_card's `(hero, layout, insets)` — both splits are photo_card's `"split"`, the id only decides how many photos go in. Also the two pure halves of the operator's reply: **`parse_reply(text) -> (field, value)`** — a reply to an open picker still replaces the headline, unless it opens `info:`, which gives the Instagram caption the operator's source and facts (`info:` with nothing after it takes them back off; the old `caption:` prefix is gone and now reads as a headline) — and **`footage_lines(footage)`**, the single 👁 line a picker shows for a `shared/vision` analysis (the headline check was removed 2026-09-16). The plan editor's **brand rows open collapsed** to one row per account group (`b:g:<i>`) with the thirteen-brand list behind `⚙ Custom…` (`b:custom` / `b:groups`) — `toggle_brand_group` is the tick rule, `modules/telegram/groups.py` the membership. **The publish step picks PLATFORMS, not pairs** — brands are already chosen one step earlier at render time, so the keyboard is 1-4 rows instead of brands×platforms. |
| `modules/telegram/headlines.py` | **Five AI headline options** (2026-10-12). An `info:` reply on an open plan card — or a URL post whose source post has text — fires `propose(info, footage, current, source)` in the background (`news_bot._start_headlines`; a newer info cancels the call in flight, an empty `info:` clears them) — one call to `HEADLINE_MODEL` (default `anthropic/claude-opus-5.5`, ~1-2¢), **no web search**: facts from the info + the vision report only. The prompt is IG-growth hook writing for a news account (specific stakes, curiosity gap the clip closes, works muted, 5-12 words / ≤`MAX_CHARS` 90 for the banner; tone switch to a straight headline on deaths/violence; unconfirmed serious claims attributed). Returns JSON `{headlines, pick, why, notes}` — the card lists them numbered with the model's pick ⭐ and a ⚠️ note (claim to verify / moment to blur); buttons `b:h:<i>` (1-5) set the headline, and option 6 is the old reply-with-your-own. Never raises (→ None, card says it failed). CLI: `py modules/telegram/headlines.py "info…" --headline "draft"`. |
| `modules/telegram/schedule.py` | **Scheduled publishing** (2026-10-13), pure half. The publish picker (after Render) has `🕒 Schedule` (`b:sched`): preset buttons (`b:at:<unix ts>` — +1h/+3h/+6h, today 18:00/21:00, tomorrow 09:00/18:00, absolute so a late tap means what it showed) or a REPLY to the picker that `parse_when` reads as a time (`18:30` = today or tomorrow if passed, `tomorrow 9:00`, `14.10 18:30`, `14.10.2026 18:30`, `+2h`/`+90m`/`in 1h30m`); a reply that isn't a time is NOT taken as a headline there. Times are **Europe/Chisinau** (`SCHEDULE_TZ`); 1 min..30 days ahead (`check`). `to_payload`/`from_payload` store the post **by brand name** and rebuild it against `config.BRANDS` at fire time (a removed brand or account drops out and is named). news_bot's half: the row goes into queue_store's **`scheduled` table** (pending → running → done/failed, or cancelled; `claim_scheduled` is the fire-once guard), the renders MOVE to `TG_DATA_DIR/media/scheduled/` (both sweeps are flat, so they never delete a waiting render), a JobQueue `run_once` fires `_run_scheduled` → `_do_publish` (no 60 s countdown — it was deliberate, and `✕ Cancel schedule` (`s:<id>:x`, DB-routed, works after a restart) is there until it fires). Startup (`_restore_scheduled`) re-arms pending rows (overdue ones fire at once) and marks a row a restart caught mid-publish **failed, never re-fired**, with a warning in the group (some platforms may have it). `/scheduled` lists what's waiting. |
| `modules/telegram/bundle.py` | **Bundle mode (2026-10-18), pure half.** Ten IG accounts post the same videos and identical videos land wildly differently per account, so every account posting is another chance: a bundle gives EVERY active account (`BUNDLE_ACCOUNTS`, default = brands with IG; remove one to pause it) exactly one of its videos. `assign(videos, accounts, history)`: the first A videos split as evenly as possible (3 on 10 = 4/3/3), which account gets which is random every time, and a matching keeps a video off an account whose reel log says it already posted it whenever another valid assignment exists; videos past A are carried into a new open bundle. `timetable`: one post at a time with a random `BUNDLE_GAP_MIN_S`..`MAX_S` (2-8 min) gap, never more than `BUNDLE_MAX_COPIES` (2) of one video per `BUNDLE_COPY_WINDOW_S` (30 min) — that cap outranks the gap (a 1-video bundle takes ~2.5 h); **integer seconds** (a float clock jumped to `oldest + window` looped forever). Also the bundle messages/keyboards (callback namespace `u:<verb>:<bundle id>`, DB-routed) and the weekly report maths (`account_stats` — follows are the follower DELTA, the Graph API has no per-Reel follows metric; `bundle_spread`; `copies_comparison`). **news_bot's half**: 📦 Bundle on a video plan card (`b:bundle`) opens one with that card's platforms; while it is open every new single video joins with NO tap as a one-line message (`_join_bundle`, files moved to `media/bundles/<id>/` out of the sweep) whose `info:` reply starts its AI headlines — the model's ⭐ pick becomes the headline unless another is tapped or typed; 🗑 Remove this one; 🎬 Render bundle refuses until every video has info, then `_render_bundle` assigns, runs the SINGLE-POST pipeline per video for its accounts (`_render_video` — split out of `_do_render` — and `_ig_captions`, so each video's captions come only from its own info/headline/source), posts ONE summary (🚀 Publish / 🔀 Reshuffle — re-draws and renders only new pairs / ✕); 🚀 Publish (`_publish_bundle`, or straight away with `BUNDLE_AUTO_PUBLISH=1`) writes one `scheduled` row per account (`bundle_id` column; captions + bundle meta in the payload) starting `BUNDLE_FIRST_POST_S` later; an IG account whose live `content_publishing_limit` is full rolls +24 h and is named. A bundle post that fails keeps its render and gets 🔁 Retry (`s:<id>:r`, failed platforms only); the others go on. Three taps for any number of videos. `/bundle` re-posts the open (or ready) bundle with its buttons; open bundles are restored into `_pending` at startup (`_restore_bundles`), a render a restart cut off goes back to open. **Reel log**: every IG reel the bot publishes (bundle or not) → `reel_log` (video_key = source URL or Telegram file_unique_id, bundle id, copy count, followers at post); the hourly `reel-insights` job stores views/reach/shares/saved/comments + followers at 24 h and 72 h (`graph.reel_insights` — a token without the permission is reported in the group once); `weekly-report` (Mondays 09:00) posts the report and the Account status reminder. |
| `modules/telegram/groups.py` | **Account groups (GMN / JNN)** — the one thing both news-bot pickers collapse behind. Thirteen brands is thirteen rows, but a post goes to a whole family, so both pickers OPEN COLLAPSED to one row per group with the full list behind `⚙ Custom…` (`⬅ Groups` goes back). Membership lives in ONE place: `"group": "GMN"` in `credentials/brands/<name>.json` → `BRAND_<NAME>_GROUP` → `brand["group"]`. Tapping a group fills it, tapping a full one clears it, and a **partly** selected group fills first (`◪`) — the selection underneath is the same set either way, so a group tick and a hand edit in Custom compose. `brand_groups` (indexes into the brand list; skips brands with no logo.png — they can't render) and `dest_groups` (indexes into TG_/YT_/TW_DESTINATIONS) — the as-is picker lists CHANNELS, not brands, so a destination is grouped by **the brand that owns that handle** (`@WsWire` is `wswire`'s `tg`), matched case-insensitively without the `@`. A destination no brand claims is Custom-only (`All` still covers it); a group that would select nothing is never offered, and with no group configured anywhere neither picker collapses. Pure, offline-testable, like `branded.py`/`reactions.py`. |
| `modules/instagram/upload_post.py` | Main poster. Pushes media to phone, drives IG's UI through the new flow (see below), archives to `posts/posted/`. Re-exports `DEVICE_ID` from `shared.config` so callers keep using `ig.DEVICE_ID`. |
| `modules/instagram/graph.py` | **Instagram publishing through the Graph API** — no phone. "Instagram API with Instagram Login" flow (Meta app, no Facebook Page), host **`graph.instagram.com` v23.0, never `graph.facebook.com`** (the `IGAA…` tokens only work on the Instagram host). Plain `requests`. Creds per account: `IG_GRAPH_<ACCOUNT>_ACCESS_TOKEN` / `_USER_ID` (account uppercased, non-alnum → `_`, same rule as the Twitter poster; `IG_` alone belongs to the phone accounts). `publish_photo(url, caption, account)` / `publish_reel(url, caption, account)`: POST `/{user}/media` (image_url, or video_url + `media_type=REELS`) → poll `GET /{container}?fields=status_code` until FINISHED (ERROR/EXPIRED and a 10-min timeout fail) → POST `/{user}/media_publish`. The media must sit at a **public https URL** (`shared/public_media.py`) — images JPEG only; 100 API posts per account per rolling 24 h. Caption trimmed to 2200 on a word boundary. Returns the Twitter poster's `{"status": "success"\|"failed", "id"\|"error"}` dict and never raises for API trouble. `refresh_token(account)` (GET `/refresh_access_token?grant_type=ig_refresh_token`) rewrites the token line in `.env` **in place** (keeping the file's CRLF/LF), stamps `IG_GRAPH_<ACCOUNT>_TOKEN_REFRESHED=YYYY-MM-DD` next to it and updates `os.environ`; `refresh_stale(accounts, max_age_days=7)` is what the news bot's daily job calls (no stamp = unknown age = refresh; a token < 24 h old can't be refreshed — stamp it by hand when pasting one). Blocking; the bot uses `asyncio.to_thread`. CLI: `py modules/instagram/graph.py --account wswiremedia --whoami` / `--refresh` / `--photo URL --caption "…"` / `--reel URL --caption "…"`. |
| `modules/instagram/caption.py` | **The Instagram caption (redesigned 2026-10-18): hook, context, question, hashtags.** Facts come from people, in trust order: **(1)** the operator's `info:`, **(2)** the headline, **(3)** the SOURCE POST the clip came from (`reel_downloader.source_post`), **(4)** vision's MEDIA NOTES — `user_message` lays them out as `OPERATOR'S INFO: … / HEADLINE: … / SOURCE POST (X): … / MEDIA NOTES: …`. `_SYSTEM` is the operator's spec word for word (+ a LANGUAGE: English line and one clarifying sentence: a rescue everyone survived still gets a question): **hook** ≤90 chars, keywords first, states what happened; **context** 1-2 sentences ≤220 chars, what the clip doesn't show; one **question** about this story (a sober line or none on deaths/serious injury); **8 hashtag candidates** most relevant first. **No calls to action at all** — the share line, `_GROWTH_RULES`, the size guide, `ANGLES`, the suggestion round and the footage prompt are gone. No web search (`searchless`). `expand(headline, footage, model, info, source)` → the base body; `compose(headline, body)` puts the hook on line 1 (the brand headline only when the model skipped it, `HOOK_MAX` 120), logs outside 150-400 chars before tags, hard cap 2200 keeping the tag line. **Per account**: `plan` (one unstyled English brand keeps the base; everyone else rewrites) → `rephrase(prose, lang, style)` (searchless `IG_CAPTION_VARIANT_MODEL`): same facts and shape, a different hook / context wording / question, the brand's `writing_style` as **tone only** (each is a tone line + a *preferred* question type, "otherwise any question specific to the story"); a **non-English** rewrite is wholly in that language and ends with **its own 8 native candidates**. **Hashtags**: `choose_hashtags({brand: candidates})` = ONE `hashtags.lookup` for every brand, then `hashtags.select` per brand (up to `STORY_HASHTAGS` 4); `finish` puts the brand's own tag (`brand_tag`, from the brand NAME) first — `MAX_HASHTAGS` 5 — and drops siblings' tags. `split_tags` separates prose and candidates. `pinned_comment(text, source)` = one extra source fact or a sharper question, with `credit(source)` (` via @handle` / ` via u/handle` / ` via Reddit`) appended in Python — a handle is never model-written. `youtube_description` cuts a finished caption for Shorts. `captions_for` runs the whole thing blocking (CLI / trace). **Never raises** (failures → the bare headline + brand tag; a failed rewrite → the base). No `temperature`; roomy `max_tokens` 8000 (OpenRouter reserves the worst case — an uncapped call 402'd on 2026-09-09). `IG_CAPTION_ENABLED=0` is the kill switch. CLI: `py modules/instagram/caption.py --media clip.mp4 --info "…" --source "…" --platform x --brands wswire,vestra24 "headline"`. |
| `modules/instagram/hashtags.py` | **Measured hashtag sizes, ONE pass (2026-10-18).** Apify's `instagram-hashtag-stats` actor (`APIFY_TOKEN`, ~$0.002 a tag) measures every brand's candidates in one `lookup`; `select(candidates, counts, limit=4, fill=3)` keeps the **5k-200k** ones (`HASHTAG_MIN_POSTS`/`_MAX_POSTS`) in the model's relevance order, and when fewer than 3 are in band fills up to 3 with the most relevant remaining candidates whatever their size; never a tag under `HASHTAG_FLOOR_POSTS` (500; 0 = an invented compound); **never** Apify's related tags (that is where #futsall came from). Logs one line per candidate (count + in band / relevance fallback / dropped / not picked). The multi-round `refine`, `nearest` and `HASHTAG_TARGET`/`_ROUNDS` are gone. **Non-Latin tags are UNMEASURED** (`measurable`): the actor URL-encodes them and answers `postsCount: 0` with no text count (seen on #спасение), so they are never sent and fill by relevance instead of being dropped. `norm` keeps Unicode letters. **Actor bug: numeric `postsCount` is 100x too big for every "K" count** — `parse_count` reads the TEXT field `posts`. An article is never posted twice by construction — `pending()` returns only `status='new'`, publishing sets `posted`, and `UNIQUE(site, wp_id)` + `INSERT OR IGNORE` blocks re-entry; only `--force-latest` re-posts. `main._now()` is the single clock so the day boundary is testable), `wp.py` (REST poller — refetches the last 20 with `_embed` and filters by stored id, **never a `?after=` watermark**, which loses backdated and scheduled posts permanently), `rewrite.py` (article → post, one OpenRouter call, degrades to the article's own lede; `--sample` is the prompt-tuning harness), `publish.py` (media passed to Telegram **as a URL** — no download, no big-file path; `compose()` reserves the article link's length before trimming so the link can't be truncated off a long post), `orders.py` (views per post, bonus every 5th against the **channel** link, delayed random reactions — every function takes a `site` because service ids are per site, and a global would bill one client's growth to another's balance), `smm.py`, `store.py`, `sites/*.json`. See `modules/newsroom/README.md`. |
| `shared/monitoring/` | Alerting, all email, all inert until `ALERT_SMTP_HOST`+`ALERT_EMAIL_TO` are set: `errmail.py` (root-logger handler — every logged ERROR/traceback is mailed per occurrence from a worker thread; `install(tag)` is called by news_bot, collector, dispatcher, telegram_bot, server.py), `heartbeat.py` (healthchecks.io dead-man pings **from inside each process's own loop** — a wedged loop must stop them; `HEALTHCHECK_URL_*` per process), `checks.py` (5-min systemd-timer CLI: CPU, disk, memory + hourly BulkFollows/OpenRouter balances vs `ALERT_*` floors; alert on crossing + daily reminder + recovery notice, state in `data/monitor_state.json` — a condition is stamped only when the mail actually left, so a failed send retries next tick; a floor of 0 disables a leg; one timer covers the newsroom bot's BulkFollows key too; `--test` sends one test email and exits 0/1; installs errmail on itself with tag `monitor`), `mailer.py` (SMTP; never raises, never logs ≥ERROR — that would loop through errmail). See `docs/DEPLOY.md` "Monitoring". |
| `swipe_stats.json` / `swipes.txt` | Calibration data feeding `human_swipe.py` (generated by `analyze_swipes.py`; live alongside it in `modules/instagram/`). |
| `ui/` | Angular frontend (`ng serve` on `:4200`, proxies `/api/*` → `:8000`). |
| `posts/` | Shared queue at the repo root. `posts/posted/` holds archives (move-on-success). |

## Running the system

Install Python deps (first time):

    py -m pip install -r requirements.txt

Backend (one terminal):

    py -m uvicorn server:app --reload --port 8000

UI (another terminal):

    cd ui
    npm start

Telegram bot (optional, another terminal — needs `.env` credentials):

    py modules/telegram/telegram_bot.py

News pipeline (each in its own terminal — needs `.env` credentials). All three
are needed for the Telegram autopilot: the collector supplies stories, the
dispatcher scores them, the news bot posts them.

    py modules/telegram/collector.py    # collects source-channel posts into the SQLite queue (first run: phone-code login)
    py modules/telegram/dispatcher.py   # the smart filter: scores queued items, auto-uploads >=YT_AUTO_MIN_SCORE videos to YouTube
    py modules/telegram/news_bot.py     # manual broadcaster + Telegram autopilot (drip + reaction asks)

Big videos (branding / YouTube past 20 MB) need one interactive login for the
news bot's MTProto client — same account as the collector, separate session:

    py modules/telegram/mtproto.py --login

Autopilot control, in the news bot's control group: `/queue` (what's queued and
what posts next), `/autopilot on|off`, `/asks` (unanswered reaction asks),
`/next` (drip one item now). Preview without posting:

    py modules/telegram/autopilot.py --once --dry-run

Tests (offline — no Telegram, OpenRouter or BulkFollows calls):

    py -m pytest tests -q

Post manually (skip the UI, uses the next queued image):

    py modules/instagram/upload_post.py

Dump the current IG screen for selector hunting:

    py modules/instagram/dump_ui.py
    # → writes ui_dump.xml; grep it for 'Create', 'Photo', etc.

## Current IG creation flow

`modules.instagram.upload_post.upload_post(d, image_path, caption_body, hashtags, kind=...)` drives the new creation UI end to end. `kind` is `"post"` (photo, default) or `"reel"` (video); the only divergence is which row gets tapped in step 4 — the rest of the flow is assumed identical and we fix selectors as IG diverges.

1. Open IG (`app_start`).
2. Tap **Profile** (bottom-right tab) — `tap_profile_tab`.
3. Tap **+** at the top of the profile screen — `tap_create_button`.
4. Tap **Post** or **Reel** in the bottom-sheet picker, per `kind`. Row order: reel / edits / post / story / highlights / live / AI / Ad — `tap_post_type`.
5. Tap the **latest thumbnail** in the gallery (auto-points at the freshly-pushed file) — `tap_latest_gallery_item`. Selectors cover both `Photo` and `Video` content-descriptions.
6. Tap **Next** after the gallery — `tap_next` (covers `text="Next"` and `description="Next"`, position-agnostic).
7. **Post only**: tap **Next** again on the filter/edit screen. Reels skip this step and land directly on the composer.
8. Tap the caption field (placeholder "Add a caption...") and inject the full caption (body + blank line + space-separated `#tags`) in one shot via uiautomator2's FastInput IME — see `inject_text`.
9. If the caption contained hashtags, the last `#tag` typically triggers IG's autocomplete strip — which overlays Share and blocks the tap. `tap_first_hashtag_suggestion` polls `dump_hierarchy()` for the row's resource-id (`row_hashtag_textview_tag_name`) and taps inside the live bounds (selector RPC silently returns count=0 for this strip on the S23, so we read XML directly). The call is **best-effort** — if the strip never appears within ~6 s we just log and continue.
10. **Dismiss the soft keyboard first** (`hide_keyboard_if_shown`) — on the reel composer Share sits in the right half of the footer at y≈2100 and the Samsung keyboard overlaps it; without this step the synthetic tap lands on the keyboard and IG never sees it. Then tap **Share**.
11. Verify the publish by dumping the hierarchy and looking for `resource-id="com.instagram.android:id/share_button"`. If it's still there the post didn't ship and we raise (`ui_dump_share_fail.xml` for inspection). Note: don't check for the caption hint text — `Write a caption…` / `Add a caption…` is the field's `hint=` attribute and stays in the XML even after the caption is filled, so it false-fires.

On success, `main()` calls `archive_post(...)` to move the image + JSON sidecar from `posts/` to `posts/posted/` so it isn't re-uploaded.

### Why FastInput IME instead of the system clipboard

On modern Samsung / OneUI, `d.set_clipboard(text)` raises `java.lang.SecurityException: Package android does not belong to 2000` — AppOpsManager won't let the shell UID claim the `android` package to call `ClipboardManager.setPrimaryClip`. We sidestep the clipboard entirely: FastInput IME (shipped inside `uiautomator2`) is activated, `send_keys` broadcasts the text to it, the IME injects it into the focused field instantly. The previous IME is restored on the way out so the user's normal keyboard isn't left swapped.
